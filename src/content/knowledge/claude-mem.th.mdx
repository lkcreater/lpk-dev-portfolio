เวลาใช้ coding agent ทำงานต่อเนื่องหลายวัน สิ่งที่ต้องเล่าใหม่มักเป็นเหตุผลเบื้องหลังโค้ด เช่น ทำไมเลือกวิธีนี้ ลองอะไรแล้วไม่ผ่าน และงานค้างอยู่ตรงไหน **[Claude-Mem](https://docs.claude-mem.ai/introduction)** เป็นเครื่องมือที่ช่วยเก็บบริบทเหล่านี้ข้าม session โดยจับข้อมูลการใช้เครื่องมือ สรุปสิ่งที่เรียนรู้ และนำกลับมาให้ Claude Code ใช้ในรอบถัดไป

บทความนี้เรียบเรียงจากเอกสารทางการที่ตรวจเมื่อ 31 ตุลาคม 2026 พร้อมตัวอย่าง workflow สำหรับนำไปทดลอง

## Claude-Mem จำอะไรให้เรา

Claude-Mem เป็นระบบ persistent memory ที่ทำงานร่วมกับ Claude Code เมื่อติดตั้งแล้วจะคอยเปลี่ยนกิจกรรมระหว่างทำงานให้เป็น **observation** หรือบันทึกความรู้ที่ค้นคืนได้ แนวคิดคือเก็บสาระสำคัญให้ใช้ต่อ แทนการเริ่มอธิบายโปรเจกต์ใหม่ทุกครั้ง ตาม[บทนำของโครงการ](https://docs.claude-mem.ai/introduction)

สำหรับการจัด workflow ผมมองว่าไฟล์คำสั่งโปรเจกต์เหมาะกับกติกาที่ทีมตั้งใจให้ทำตาม ส่วนความจำจากการทำงานเหมาะกับประวัติว่าเคยพบอะไร ทั้งสองอย่างควรช่วยกัน: กติกาบอกทิศทาง ประวัติช่วยอธิบายที่มา และโค้ดปัจจุบันยังเป็นสิ่งที่ต้องเปิดตรวจ

## จากการใช้ tool ไปเป็นบริบทครั้งถัดไป

[Getting Started](https://docs.claude-mem.ai/usage/getting-started) อธิบายวงจรการทำงานไว้ดังนี้

1. **เปิด session** — โหลด observation และสรุปงานล่าสุดของโปรเจกต์เข้า context
2. **ทำงานตามปกติ** — เก็บกิจกรรมจากเครื่องมือ เช่น อ่านไฟล์ แก้โค้ด ค้นหา และรันคำสั่ง
3. **ประมวลผลความรู้** — worker สกัดหัวข้อ ข้อเท็จจริง ประเภทของงาน และไฟล์ที่เกี่ยวข้อง
4. **สร้างสรุป** — เมื่อเกิด Stop hook จะสรุปสิ่งที่ค้นพบ งานที่เสร็จ และขั้นตอนถัดไป เพื่อใช้ต่อใน session ใหม่

ด้านระบบมี hooks เชื่อมกับ lifecycle ของ Claude Code, worker สำหรับประมวลผล และ SQLite พร้อม FTS5 สำหรับค้นข้อความ ส่วน Chroma เป็นตัวเลือกสำหรับ semantic search มี viewer ให้ดูความจำด้วย ตาม[Architecture Overview](https://docs.claude-mem.ai/architecture/overview)

ข้อมูลกับการตั้งค่าอยู่ใน `~/.claude-mem/` โดยมี `settings.json` สำหรับปรับพฤติกรรมและบริบทที่ฉีดกลับเข้า session ดูรายละเอียดใน[Configuration](https://docs.claude-mem.ai/configuration) การเก็บฐานข้อมูลบนเครื่องกับการเลือกโมเดลประมวลผลเป็นคนละเรื่อง จึงควรตรวจ provider ที่ตั้งไว้ด้วย

## เริ่มติดตั้ง

ใน Claude Code เพิ่ม marketplace และติดตั้ง plugin แล้วเปิด Claude Code ใหม่

```text
/plugin marketplace add thedotmack/claude-mem
/plugin install claude-mem
```

หรือติดตั้งผ่าน terminal โดยระบุให้ใช้ Anthropic plan ของตัวเอง

```bash
npx claude-mem install --provider claude
```

คำสั่ง `npx claude-mem install` แบบ interactive ปัจจุบันเลือก CMEM Pro ไว้ล่วงหน้า ส่วน `--provider claude` ข้ามขั้นตอน sign-in ของตัวติดตั้งและใช้ plan ของเรา ควรตรวจตัวเลือกและโควตาก่อนยืนยัน ตาม[Installation](https://docs.claude-mem.ai/installation)

## ค้นความจำแบบเปิดรายละเอียดเท่าที่จำเป็น

ความจำที่สะสมไว้จะมีประโยชน์เมื่อค้นเจอสิ่งที่ตรงกับงานปัจจุบัน [Smart Memory Search](https://docs.claude-mem.ai/usage/search-tools) ใช้แนวทาง **progressive disclosure** ผ่าน skill และ MCP tools โดยค่อย ๆ เปิดข้อมูลสามชั้น

- **`search`** — ดูดัชนีแบบย่อ เช่น ID ชื่อเรื่อง วันที่ และประเภท
- **`timeline`** — ดูเหตุการณ์ก่อนและหลังรายการที่สนใจ เพื่อเข้าใจบริบท
- **`get_observations`** — อ่านรายละเอียดเต็มเฉพาะ ID ที่เลือก

ตัวอย่างคำถามที่นำไปปรับใช้ได้

```text
ค้นประวัติของโปรเจกต์นี้ว่าเราเคยแก้ปัญหา login redirect อย่างไร
เริ่มจากรายการที่เกี่ยวข้อง แล้วอ่านรายละเอียดเฉพาะรายการที่ตรงประเด็น
สรุปเหตุผลที่เลือกวิธีแก้ พร้อมอ้างอิง observation ID
```

ผมจะให้ agent เปิดไฟล์ปัจจุบันเทียบกับผลค้นหาก่อนแก้เสมอ เพราะเหตุผลที่ถูกต้องในวันที่บันทึกอาจไม่ตรงกับระบบหลัง refactor แล้ว

## ดูงานย้อนหลังและเพิ่มบริบทรายโฟลเดอร์

**My Work** เป็น viewer บนเครื่องสำหรับดูคำขอ ความคืบหน้า ผลงาน และขั้นตอนที่รอเรา เปิดผ่าน URL ของ worker ที่ Claude-Mem แสดงให้ หน้า viewer อ่านข้อมูลที่บันทึกไว้ได้โดยไม่ต้องเรียกโมเดลใหม่ ตาม[คู่มือ My Work](https://docs.claude-mem.ai/usage/my-work)

อีกฟีเจอร์คือสร้าง timeline กิจกรรมใน `CLAUDE.md` ของโฟลเดอร์ย่อย ซึ่ง**ปิดไว้โดยค่าเริ่มต้น** หากต้องการใช้ ให้เพิ่มค่านี้ใน `~/.claude-mem/settings.json` โดยรวมกับค่าที่มีอยู่ ตาม[Folder Context Files](https://docs.claude-mem.ai/usage/folder-context)

```json
{
  "CLAUDE_MEM_FOLDER_CLAUDEMD_ENABLED": "true"
}
```

เนื้อหาที่สร้างจะอยู่ในส่วนที่ครอบด้วยแท็กเฉพาะ และข้อความที่เราเขียนนอกส่วนนั้นจะถูกเก็บไว้ หากเปิดใช้กับทีม ควรตกลงกันว่าจะ commit timeline เหล่านี้หรือเก็บเฉพาะเครื่อง เพราะไฟล์อาจเปลี่ยนบ่อย

## คุมข้อมูลที่ต้องการให้จำ

**Private tags** ใช้ครอบข้อความที่ไม่ต้องการให้บันทึกลงความจำของ Claude-Mem เช่น บริบทชั่วคราว ตาม[คู่มือ Private Tags](https://docs.claude-mem.ai/usage/private-tags)

```text
<private>
บริบทนี้ใช้ประกอบการวิเคราะห์เฉพาะ session ปัจจุบัน
</private>

ช่วยวิเคราะห์ทางเลือกโดยยังไม่บันทึกบริบทส่วนนี้เป็นความจำ
```

Claude ยังเห็นข้อความนี้ในบทสนทนาปัจจุบัน แท็กควบคุมการบันทึกของ Claude-Mem จึงไม่ได้ป้องกันข้อมูลจากโมเดลที่กำลังสนทนาด้วย

**Auto-redaction** เป็นอีกชั้นที่ต้องเปิดเอง ใช้ regex ตรวจรูปแบบ secret แล้วแทนด้วย placeholder ก่อนจัดเก็บ เพิ่มค่านี้ใน settings เดิม ตาม[Auto-Redaction](https://docs.claude-mem.ai/usage/auto-redaction)

```json
{
  "CLAUDE_MEM_REDACT_ENABLED": "true"
}
```

การตรวจตาม pattern มีขอบเขต จึงไม่ควรใช้แทนการจัดการ secret และสิทธิ์เข้าถึงข้อมูลของโปรเจกต์

นอกจากนี้ telemetry เปิดโดยค่าเริ่มต้น เอกสารระบุว่าเป็นสถิติการใช้งานแบบไม่ระบุตัวตน หากต้องการปิด ใช้คำสั่งตาม[คู่มือ Telemetry](https://docs.claude-mem.ai/telemetry)

```bash
npx claude-mem telemetry disable
```

## ลองกับงานที่กลับมาทำซ้ำก่อน

ผมแนะนำให้เริ่มกับโปรเจกต์ที่ต้องกลับมาแก้หลายรอบ เช่น bug ที่เกี่ยวข้องกับการตัดสินใจเดิม แล้วทดลองแบบนี้

1. ให้ agent วิเคราะห์และแก้ปัญหาพร้อมตรวจผลตามปกติ
2. เปิด viewer ดูว่าบันทึกเหตุผลและสิ่งที่เรียนรู้ไว้ถูกต้องหรือไม่
3. เริ่ม session ใหม่ แล้วถามถึงงานเดิมโดยไม่วางประวัติแชตทั้งหมดซ้ำ
4. ตรวจคำตอบกับ observation ที่อ้างถึงและโค้ดล่าสุดก่อนทำงานต่อ

เกณฑ์ที่ผมจะใช้ประเมินคือช่วยลดการเล่าซ้ำได้แค่ไหน ค้นเหตุผลเก่าเจอหรือไม่ และมีข้อมูลที่ไม่อยากเก็บปะปนหรือเปล่า ส่วนคำสั่งทดสอบ กติกาทีม และข้อสรุปสำคัญที่ต้องให้คนตรวจยังควรมีเอกสารที่ดูแลอย่างตั้งใจ

ถ้ากำลังจัด workflow ของ Claude Code อ่านต่อเรื่อง[การแบ่งงานด้วย subagent](/th/knowledge/claude-code-subagents) และ[Agent Skills](/th/knowledge/skills-sh) เพื่อวางทั้งวิธีทำงานและบริบทที่ต้องใช้ให้เหมาะกับโปรเจกต์
