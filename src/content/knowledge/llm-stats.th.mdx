ทุกสัปดาห์มีโมเดล AI ใหม่ออกมา และทุกค่ายบอกว่าของตัวเองเก่งที่สุด คำถามที่นักพัฒนาต้องตอบจริง ๆ ไม่ใช่ "โมเดลไหนดีที่สุด" แต่เป็น "โมเดลไหนเหมาะกับงานนี้ ในงบนี้ และความเร็วที่ผู้ใช้รับได้" **[LLM Stats](https://llm-stats.com/)** คือเว็บที่รวบรวมข้อมูลเหล่านี้ไว้ในที่เดียว ทำให้เปรียบเทียบได้เร็วโดยไม่ต้องไล่อ่าน model card ทีละค่าย

## LLM Stats คืออะไร

LLM Stats เรียกตัวเองว่า "The AI Benchmarking Hub" เป็นแพลตฟอร์มอิสระที่จัดอันดับและเปรียบเทียบโมเดลภาษาหลายร้อยตัว จากทุกค่ายใหญ่ ทั้ง OpenAI, Anthropic, Google, Meta, DeepSeek, Qwen, Mistral, xAI และอื่น ๆ ทั้งโมเดลปิดและ open-weights

ทีมผู้ก่อตั้งอธิบายเหตุผลที่ทำเว็บนี้ว่า benchmark ส่วนใหญ่ถูกเลือกโดยคนที่ขายโมเดลเอง ผลลัพธ์จึงมักถูกคัดมาเฉพาะที่ดูดี LLM Stats จึงพยายามรวมผลจากหลายแหล่งไว้ในที่เดียว และระบุชัดว่าคะแนนไหนค่ายรายงานเอง คะแนนไหนตรวจสอบโดยอิสระ

## มีข้อมูลอะไรบ้าง

- **คะแนน benchmark** เช่น GPQA Diamond, MMLU-Pro, SWE-Bench Verified, LiveCodeBench, AIME, MATH, HumanEval และ MMMU พร้อมหน้าอธิบายของแต่ละ benchmark
- **ราคา** ต่อ 1 ล้าน token ของแต่ละผู้ให้บริการ ทางเว็บระบุว่าดึงจากหน้าราคาทางการ แล้วตรวจทานกับบิลจริงอีกชั้น
- **ความเร็ว** วัดเป็น token ต่อวินาทีจากการเรียก API จริง
- **Context window** ขนาดสูงสุดที่แต่ละโมเดลรับได้
- **License และผู้พัฒนา** แยกโมเดลปิดกับ open-weights ได้ชัด
- **LLM Stats Score** คะแนนรวมที่สรุปหลาย benchmark เป็นตัวเลขเดียว แยกเป็น 6 หมวด ได้แก่ Reasoning, Coding, Agent, Math, Long Context และ Vision

## เครื่องมือที่ใช้บ่อย

- **Leaderboard หลัก** กรองตามราคา ความเร็ว จำนวน parameter, license และช่วงเวลา (ทั้งหมด, 90 วัน, 30 วัน)
- **Leaderboard ตามงาน** เช่น Best AI for Coding, Writing, Math, Research, Long Context, Tool Calling และ Reasoning รวมถึงหมวดเฉพาะอาชีพ อย่าง web development, UI design, การเงิน และกฎหมาย
- **Open LLM Leaderboard** ดูเฉพาะโมเดล open-weights เหมาะกับงานที่ต้อง self-host
- **Compare** เทียบโมเดลหลายตัวแบบข้างต่อข้างในทุกมิติ
- **Pricing comparison** ดูความคุ้มค่าเทียบราคากับประสิทธิภาพ
- **Arena** การจัดอันดับแบบตัวต่อตัว เช่น coding arena
- **AI News** และจดหมายข่าวรายสัปดาห์ สรุปโมเดลใหม่และผล benchmark ล่าสุด
- **ค้นหาเร็ว** ด้วย `⌘K` ทั้งชื่อโมเดลและชื่อค่าย

## LLM Stats Score คิดยังไง

จุดที่ชอบคือหน้า [methodology](https://llm-stats.com/methodology/llm-stats-score) อธิบายแนวคิดไว้ค่อนข้างตรงไปตรงมา

- **ปรับสเกลก่อนรวม** เพราะคะแนน 80 ใน benchmark หนึ่งกับอีก benchmark หนึ่งมีความหมายไม่เท่ากัน จึงเทียบโมเดลกันภายใน benchmark เดียวกันก่อนแล้วค่อยรวม
- **ไม่มีผล ไม่ได้แปลว่าสอบตก** โมเดลที่ยังไม่มีผลในบาง benchmark จะไม่ถูกให้ศูนย์ แต่คะแนนจะมีความไม่แน่นอนสูงกว่าแทน
- **แยกแหล่งที่มาชัด** คะแนนที่ค่ายรายงานเองจะมีป้ายกำกับและลิงก์ไปแหล่งที่มา ส่วนผลที่ตรวจสอบโดยอิสระจะถูกระบุแยกไว้

และทางเว็บก็บอกข้อจำกัดไว้เองว่า คะแนนนี้วัดได้แค่ความสามารถที่อยู่ในชุดทดสอบ และ **ไม่ใช่คำแนะนำว่าควรใช้โมเดลไหนกับงานเฉพาะ**

## Data API และ MCP สำหรับนักพัฒนา

ถ้าอยากเอาข้อมูลไปใช้ในระบบของตัวเอง เช่น ทำ dashboard เลือกโมเดล หรือให้ AI agent เช็กราคาก่อนเลือกโมเดล มี Data API ให้ใช้

```bash
curl -H "Authorization: Bearer $API_KEY" \
  "https://api.zeroeval.com/stats/v1/models?organization=anthropic&limit=2"
```

endpoint หลักมี `/stats/v1/models` (รายชื่อโมเดล ราคา และคะแนนหมวด), `/stats/v1/models/{id}` (คะแนนทุก benchmark ของโมเดลนั้น), `/stats/v1/benchmarks`, `/stats/v1/rankings` และ `/stats/v1/updates` สำหรับดูโมเดลที่เพิ่งเพิ่มเข้ามา

ณ ตอนที่เขียน (ต.ค. 2026) แพ็กเกจฟรีได้ 250 response ต่อวัน และมีแพ็กเกจเสียเงินสำหรับใช้งานหนักหรือเชิงพาณิชย์ นอกจากนี้ยังมี MCP server ที่เชื่อมกับ agent อย่าง Claude Code, Cursor และ Windsurf ได้ ให้ agent ถามข้อมูลโมเดลได้เองระหว่างทำงาน

## วิธีใช้เลือกโมเดลสำหรับโปรเจกต์จริง

ขั้นตอนที่ผมใช้

1. **เริ่มจาก leaderboard ที่ตรงกับงาน** ถ้าทำ coding agent ให้ดู Best AI for Coding หรือ Tool Calling อย่าเริ่มจากคะแนนรวม
2. **กรองด้วยข้อจำกัดจริง** ตั้งงบต่อ 1 ล้าน token ความเร็วขั้นต่ำที่ผู้ใช้รับได้ และ context ที่ต้องใช้ ถ้าต้อง self-host ก็กรองเฉพาะ open-weights
3. **เลือก 2–3 ตัวมาเทียบใน Compare** ดูว่าตัวไหนคุ้มที่สุดในมิติที่สำคัญกับงานเรา
4. **เปิดดูที่มาของคะแนน** เช็กว่าเป็นตัวเลขที่ค่ายรายงานเอง หรือผ่านการตรวจสอบแล้ว
5. **ทดสอบกับงานของเราเอง** เตรียมชุด prompt จากงานจริงสัก 10–20 ข้อ แล้ววัดผลเอง ก่อนตัดสินใจ

แนวคิดเดียวกันนี้ใช้ตอนแบ่งงานให้ทีม agent ได้ด้วย เช่น งานที่อ่านและเขียนโค้ดเยอะตามแผนที่ชัด ใช้โมเดลที่เร็วและคุ้ม ส่วนงานวางแผนและตรวจทานใช้โมเดลที่เก่งด้าน reasoning (ดูตัวอย่างใน[บทความ Claude Code Subagents](/th/knowledge/claude-code-subagents))

## ข้อดี

- **ข้อมูลครบในที่เดียว** คะแนน ราคา ความเร็ว และ context อยู่หน้าเดียวกัน ไม่ต้องเปิดหลายแท็บ
- **อัปเดตต่อเนื่อง** โมเดลใหม่และผล benchmark ใหม่ถูกเพิ่มเข้ามาเร็ว
- **โปร่งใสเรื่องที่มา** แยกคะแนนที่ค่ายรายงานเองกับที่ตรวจสอบแล้ว และมีหน้า methodology ให้อ่าน
- **มีมุมมองตามงาน** ไม่ได้มีแค่อันดับรวม แต่มี leaderboard แยกตามประเภทงานและอาชีพ
- **ต่อยอดได้** มี API และ MCP ให้เอาข้อมูลไปใช้ในระบบหรือใน agent

## สิ่งที่ควรระวัง

- **Benchmark ไม่ใช่งานของเรา** คะแนนสูงในข้อสอบมาตรฐานไม่ได้รับประกันว่าจะทำงานเฉพาะของเราได้ดี ต้องทดสอบเองเสมอ
- **คะแนนที่ค่ายรายงานเอง** ขึ้นกับวิธีทดสอบที่แต่ละค่ายเลือก ควรดูป้ายกำกับแหล่งที่มาทุกครั้ง
- **ข้อมูลเปลี่ยนเร็ว** ราคาและอันดับเปลี่ยนได้ทุกสัปดาห์ ตัวเลขในบทความนี้ (รวมถึงราคาแพ็กเกจ API) อาจไม่ตรงกับปัจจุบันแล้ว
- **คะแนนรวมซ่อนรายละเอียด** โมเดลที่คะแนนรวมใกล้กันอาจเก่งคนละด้าน ควรดูคะแนนรายหมวดประกอบ
- **มีบริการเชิงพาณิชย์ด้วย** ทีมงานมีรายได้จาก API และบริการ benchmark ข้อมูลยังมีประโยชน์มาก แต่ควรใช้ประกอบกับแหล่งอื่นด้วย

## สรุป

LLM Stats เหมาะเป็นจุดเริ่มต้นเวลาต้องเลือกโมเดล AI ช่วยตัดตัวเลือกจากหลายร้อยตัวให้เหลือไม่กี่ตัวได้ในไม่กี่นาที ด้วยข้อมูลคะแนน ราคา และความเร็วที่อยู่ในที่เดียว แต่การตัดสินใจสุดท้ายควรมาจากการทดสอบกับงานจริงของเราเอง ใช้ตัวเลขเพื่อ "คัดตัวเลือก" ไม่ใช่เพื่อ "ตัดสิน"
